# 预同步完成与切换条件

[English](precopy.md) | 简体中文

本文定义 `pre-copy` 的成功、完成和后续切换条件，适用于本工具支持的 local-path 数据卷；单实例多 PVC 必须全部校验通过后才能切换。在线副本仅用于减少停机期间的复制量，不是可直接启动的数据库副本。

## 三个不同的完成条件

| 状态 | 必须满足的条件 | 允许的后续动作 |
| --- | --- | --- |
| 本轮成功 | 复制 Job 成功，rsync 正常退出；复制助手退出并释放卷；相关检查和检查点保存成功 | 再执行一轮，或判断是否完成预同步策略 |
| 预同步策略完成（`ready=true`） | 完成指定成功轮数；显式阈值模式下，则必须有一轮可信的实际同步耗时达标 | 重新检查源和卷，然后进入停写阶段 |
| 最终副本校验通过 | 源写进程退出；停写后最终同步成功，含内容比较和目标多余文件清理；源、目标完整摘要一致 | 改绑 PVC/PV，并在目标节点启动服务 |

`ready=true` 不等于源、目标一致，也不直接允许切换卷。命令必须带有 `--allow-downtime` 才执行迁移；即使预同步关闭，最终停写和校验也不能跳过。

## 源 PV 一直有写入时

一轮扫描结束前，已经扫描过的文件可能再次变化。rsync 成功仅表示本轮正常完成，不要求在线时的脏数据降为零，也不能据此宣称数据库一致。

可以完成数轮预同步后停止源服务，最终一次同步补齐剩余新增、修改、删除、重命名和截断。源停写后使用内容比较，避免在线复制留下同大小、同修改时间但内容不同的文件；随后再次完整比较摘要。最终同步或校验失败时禁止切换。

若持续写入令增量长期很大，按轮数完成策略仍可在允许停机时进入停写，但停机可能较长。需要更严格控制时可显式配置耗时条件；任何阈值都不是停机上限。应用退出、最终扫描、同步、完整摘要校验、挂载、启动和恢复都占用停机窗口。

## 默认策略：成功轮数

```yaml
precopy: true
precopyRounds: 3
precopyThreshold: 0s
```

每次 `apply`／`resume` 对尚未停写的卷完成指定成功轮数，再进入停写前检查。默认 3 轮是可配置的预热次数，不是数据一致性标准。中途失败的轮次不计为成功，也不会因为历史轮数已足够而忽略本次失败。

## 可选策略：显式耗时条件

```yaml
precopy: true
precopyRounds: 5
precopyThreshold: 45s
```

该示例每次执行最多尝试 5 轮；一轮成功且实际同步耗时不超过 45 秒即可结束预同步。45 秒由配置指定，不是工具统一要求。

日志和报告分别记录：

- `elapsed`／`elapsedMillis`：创建、调度、同步、清理以及等待释放卷的整轮时间。
- `sync`／`syncMillis`：属于当前复制 Job 的成功 rsync 容器运行时间，包含扫描、连接和传输，不是纯网络时间。
- `setupCleanup`：整轮时间减去实际同步时间，包含调度、清理和编排等待。
- `ready`：本次预同步策略是否完成。
- `thresholdMet`（报告兼容字段 `converged`）：仅表示显式耗时条件达标，不代表数据真正收敛或两边一致。

没有可信的容器时间（例如 Pod 已清理、出现多次尝试或状态缺失）时记为未知，不能当作零或达标。所有轮次均未满足显式条件时，保留源服务运行和检查点，停止后续批次，等待 `resume`。

## 停写前与切换前的再次检查

预同步策略完成后，必须重新确认原始源 Pod 的 UID、Ready、所在节点、同组其他副本健康及控制器未发生漂移，并确认目标临时卷归属正确、辅助 Pod 已释放卷、目标卷没有业务消费者。检查失败不进入停写。

停写后必须阻止控制器重建源实例，并确认实际写进程退出。只删除 Kubernetes Pod 对象不等于进程已退出；源节点不可达或退出情况无法证实时，不得绕过检查切换卷。最终同步和摘要校验失败时，保留检查点处理原因，不能提前启动目标服务。

最终摘要不一致会记录可恢复的失败状态。修复原因后，原任务的 `resume` 仅在源仍停写、全部卷仍保持原绑定且无额外消费者、尚未开始改绑或启动时，重新取得源摘要并执行最终同步。已经切换或可能产生目标写入后，不允许重新复制覆盖目标，也不会自动回退旧数据。

### 可选的并行完整摘要

`parallelDigest: false` 为默认值，保持“源完整摘要 → 最终 checksum 同步 → 目标完整摘要”的串行顺序。显式配置 `parallelDigest: true` 或 `plan --parallel-digest` 后，顺序改为“最终 checksum 同步 → 并发读取源、目标完整摘要 → 比较”。两种方式都必须先确认源已停写；并行方式不减少校验范围或跳过任何一致性检查。

独立存储可能通过重叠读取减少等待；共享机械盘或同一宿主机磁盘可能因争抢 I/O 变慢，默认保持串行。不承诺具体加速比例，应按现场测量选择。

## 中断、恢复与并发

- 预同步失败、取消或源身份变化时，不把该轮记录为成功；该卷保留在预同步阶段。
- 已完成预同步但尚未停写时中断，即使实例检查点已进入准备或停写阶段，只要原 Pod 仍同 UID、Ready 且没有终止时间戳，`resume` 都重新执行预同步，不能依赖可能已经过期的耗时判断。驱逐被 PDB 拒绝后续跑同样适用。
- 已进入停写阶段的卷按原检查点继续最终同步，不要求已停止的源 Pod 再在线。
- 当前按实例串行执行，某卷失败时保留当前实例的状态和保护，不进入下一实例；同实例的卷必须全部验证通过后才允许改绑。
- 新计划默认阈值为零。旧节点替换检查点仅支持查看，须由相应旧版本处理，不会静默转换为新执行流程。
- 目标服务产生新写入后，旧源数据已落后，禁止自动直接回退到旧副本。
